Ver glosarioOcultar
UVa / VJudge
Juez en línea histórico usado por CP3. Cada problema tiene un ID numérico (p. ej. UVa 573) y puede enviarse en Online Judge o VJudge.
uHunt
Tablero de seguimiento de problemas UVa clasificados por capítulo y tema de Competitive Programming 3.
AC · WA · TLE · RTE · PE
Accepted, Wrong Answer, Time Limit Exceeded, Runtime Error y Presentation Error (espacios o saltos de línea).
Big-O y regla 10⁸
Cota asintótica de operaciones. En C++ suelen ejecutarse ~10⁸ operaciones simples por segundo; en Python ~10⁷.
BSTA
Binary Search The Answer: buscar la respuesta óptima cuando el predicado de factibilidad es monótono.
DSU / UFDS
Disjoint Set Union: une conjuntos y consulta conectividad en tiempo casi constante O(α(N)).
BIT · Segment Tree
Árboles para responder sumas/mínimos por rango y actualizaciones dinámicas en O(log N).
DP (Top-Down / Bottom-Up)
Programación Dinámica: memoización recursiva o tabulación iterativa sobre subproblemas superpuestos.
MST · SSSP · APSP
Árbol de Expansión Mínima (Kruskal/Prim), caminos cortos desde un origen (Dijkstra/Bellman-Ford) y todos los pares (Floyd-Warshall).
SCC · Toposort
Componentes Fuertemente Conexas (Tarjan/Kosaraju) y orden topológico en grafos dirigidos acíclicos (DAG).
Max-Flow Min-Cut
Flujo máximo de s a t en una red de capacidades (Edmonds-Karp / Dinic), dual del corte mínimo.
KMP · Convex Hull
Búsqueda lineal de cadenas por función prefijo π y envolvente convexa mínima en O(N log N).

Estrategia de lectura recomendada por semana

1. Intuición (20 min)
Leer la sección en CPH o Skiena antes de la clase para captar la idea visual y el modelado.
2. Clase semanal (120 min)
Seguir la presentación de 10 diapositivas (semanas/semanaXX.html), la traza paso a paso y la plantilla.
3. Práctica UVa (3–4 h)
Enviar los 2 problemas resueltos de la semana en VJudge y completar al menos 2 ejercicios adicionales de CP3.
4. Profundización (opcional)
Revisar demostraciones e inducción en Erickson y las «War Stories» de Skiena.

Referencia rápida para competencias

Guía de bolsillo para elegir la complejidad objetivo según el tamaño de entrada N, copiar la plantilla base de entrada/salida rápida y depurar veredictos en UVa / ICPC.

Guía rápida: tamaño de entrada N → complejidad máxima viable

Basada en CP3 (§1.2.3) y CPH (§2.3), asumiendo un límite estándar de 1–2 segundos (~10⁸ ops/s en C++). Mueve el deslizador de N para simular qué complejidades obtienen AC o TLE:

Tamaño máximo de NPeor complejidad aceptableTécnicas típicas
N ≤ 10–11O(N!), O(N⁶)Permutaciones completas, backtracking sin poda pesada
N ≤ 16–20O(2ᴺ), O(N² 2ᴺ)Bitmask DP (TSP), subconjuntos, backtracking con podas
N ≤ 40O(2^(N/2))Meet-in-the-Middle
N ≤ 100O(N⁴)DP de 3–4 estados, Max-Flow en grafos pequeños
N ≤ 400–500O(N³)Floyd-Warshall, multiplicación de matrices, Max 2D Sum
N ≤ 2.000–5.000O(N²)DP 2D (LCS, Edit Distance, Knapsack), Bellman-Ford
N ≤ 10⁵–5×10⁵O(N log N)Sort, Binary Search, Dijkstra, Kruskal, Segment Tree, BIT
N ≤ 10⁶–10⁷O(N)DFS/BFS, Kadane, KMP, Criba, Two Pointers, DSU
N ≤ 10¹⁸O(log N) o O(1)Exponenciación binaria, Euclides, fórmulas cerradas, BSTA

import java.io.*;
import java.util.*;

public class Main {
    static BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    static StringTokenizer st;

    static String next() throws IOException {
        while (st == null || !st.hasMoreTokens()) {
            String line = br.readLine();
            if (line == null) return null;
            st = new StringTokenizer(line);
        }
        return st.nextToken();
    }

    public static void main(String[] args) throws Exception {
        StringBuilder sb = new StringBuilder();
        String tok = next();
        if (tok != null) {
            int t = Integer.parseInt(tok);
            while (t-- > 0) {
                // Resolver caso y acumular en sb
            }
        }
        System.out.print(sb);
    }
}
